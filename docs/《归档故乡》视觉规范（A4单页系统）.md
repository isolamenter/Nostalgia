# 《归档故乡》视觉规范（A4 单页系统）

> 版本：1.0  
> 适用范围：Web 端游戏画面、React 记录空间 UI、Phaser 现实空间  
> 核心命题：档案会为现在，分配一个过去。

## 一、视觉定位

《归档故乡》的界面不是常规游戏 HUD，也不是泛化的复古纸张页面，而是一张正在被阅读、核对和修改的县级档案卷宗。

视觉来自以下具体材料：

- 潮湿县城里的旧建筑、金属档案柜和低照度室内空间。
- 复写纸、目录卡、登记表、铅笔批注和氧化印泥。
- 同一事实出现两份记录时产生的套印偏差。

整体保持低饱和、克制和可读。纸张只用于散文、目录卡和章节落卷等“记录空间”，现实场景继续使用潮湿蓝黑色。禁止把整个页面统一做成泛黄纸张，也不使用无意义的大面积颗粒、邮戳和装饰编号。

## 二、标志性元素：第二份错位复写

“第二份错位复写”是本项目唯一需要被记住的强视觉动作。

表现方式：

- 在标题或关键落款背后增加一层低透明度的复写青副本。
- 副本与正文产生轻微位置偏差，不影响正文识别。
- 首次进入标题页时，副本从较大的偏移量归位一次。
- 档案最终状态使用轻微旋转的登记章表达。

使用限制：

- 不在普通正文、所有按钮或每张卡片上重复使用。
- 同一画面最多保留一个明显的错位复写焦点。
- 复写层不得强于主文字，不得制造重影阅读障碍。

## 三、A4 单页画面

### 3.1 固定比例

整个游戏显示区域固定为竖向 A4：

```text
宽 : 高 = 210 : 297 ≈ 0.707 : 1
Phaser 基准分辨率 = 630 × 891
```

页面在浏览器视口中居中，并始终等比缩放：

- 横向浏览器窗口：页面高度贴合视口，左右显示背景留白。
- 窄竖屏窗口：页面宽度贴合视口，上下显示背景留白。
- 不允许非等比拉伸。
- 不允许为了铺满窗口而裁切 A4 页面。
- 页面外区域属于阅读环境，不属于游戏可交互区域。

当前实现：`app/src/styles/index.css` 中的 `.game-app`。

```css
.game-app {
  width: min(100vw, calc(100vh * 210 / 297));
  height: min(100vh, calc(100vw * 297 / 210));
  aspect-ratio: 210 / 297;
}
```

### 3.2 页面层级

```text
80  Toast
70  标题扉页
60  存档登记
55  章节结算
50  档案抽屉
40  对话 / 散文
35  随身物件
30  HUD
24  页面扫描纹理
 0  Phaser 现实空间
```

新增界面必须进入上述层级体系，不得随意使用超大 `z-index`。

### 4.1 色彩规则

- 复写青只表达可交互、被选中或“第二份”语义。
- 印泥红只表达移出、删除、异常登记或最终状态，不作为普通装饰色。
- 纸张区域必须使用深色正文，禁止在浅纸上继续使用浅灰文字。
- 颜色不能成为状态的唯一提示；状态必须同时显示文字或形状。
- 场景颜色可以按地点变化，但必须保持低饱和，并与 UI token 处于同一冷灰体系。

## 五、字体系统

| 角色 | 字体栈 | 用途 |
|---|---|---|
| 展示 / 散文 | `Songti SC`, `STSong`, `Noto Serif CJK SC`, serif | 标题、散文、章节结算、档案标题 |
| UI / 对白 | `PingFang SC`, `Hiragino Sans GB`, `Microsoft YaHei`, sans-serif | 按钮、对白、操作说明 |
| 数据 / 元信息 | `SFMono-Regular`, `Cascadia Mono`, `Roboto Mono`, monospace | 档案编号、时间、数量、英文元数据 |

规则：

- 宋体负责叙事和记录，不用于密集的小尺寸操作按钮。
- 黑体负责动作和导航，优先保证识别速度。
- 等宽字体只用于真实的数据结构，不用于普通装饰文字。
- 中文正文常规行高为 `1.7–2.05`。
- 标题允许较大字距；正文不得使用过大的字距。
- 按钮使用句式名称，例如“保存进度”“回到标题”，不使用模糊的“确认”“提交”。

## 六、形状、边界与阴影

### 6.1 圆角

- 常规面板、按钮和档案卡：`1–2px`。
- 关闭按钮可以使用圆形。
- 禁止使用大面积 `8–16px` 的现代产品卡片圆角。
- 状态不使用胶囊标签，使用矩形登记章。

### 6.2 边界

- 主要面板：`1px solid var(--line)`。
- 档案柜和结算页顶部：额外增加 `2–3px` 复写青上沿。
- 目录卡展开处：使用虚线表达可拆分的记录层。
- 纸张上的印泥分隔线使用低透明度红色，不使用高亮纯红。

### 6.3 阴影

- 阴影用于表达纸张、抽屉和浮层的物理关系。
- 阴影颜色统一来自近黑冷色，不使用彩色霓虹光晕。
- 场景物件使用短而轻的落地阴影；浮层使用更大但低对比度的阴影。

## 七、React 记录空间组件

当前主要实现位于：

- `app/src/styles/index.css`
- `app/src/styles/panels.css`
- `app/src/ui/`

### 7.1 标题页

标题页是一张卷宗扉页，不使用居中产品卡片。

必须包含：

- 档案机构或地点。
- 卷宗编号和状态。
- 作品标题。
- 当前章节。
- 作品命题。
- “开始新的档案”和“继续上次的档案”。

标题是页面视觉焦点，也是错位复写效果的主要使用位置。

### 7.2 HUD

- 位于页面顶部，表现为窄登记条。
- 左侧显示“当前位置”和地点名称。
- 右侧显示档案、物件和存档入口。
- 操作提示置于地点信息下方，使用等宽小字。
- HUD 从上向下渐隐，避免形成不透明导航栏。
- HUD 不得遮住玩家附近的主要交互区域。

### 7.3 对话与散文

对话系统必须保留两种明确不同的视觉模式。

对白模式：

- 深色半透明面板。
- 人物姓名表现为“口述记录”标签。
- 正文使用 UI 黑体。
- 打字机和点击跳过提示保持克制。

散文模式：

- 使用旧票据纸背景。
- 正文使用宋体和更大的行高。
- 左侧保留一条低透明度印泥登记线。
- 页脚可标记“第二份 / COPY 02”。

选项：

- 使用批注式列表。
- 不使用没有内容含义的 `01 / 02 / 03` 编号。
- 使用小菱形或边线提示可选择性。
- 选项文字必须描述玩家将做什么。

### 7.4 档案抽屉

- 从页面右侧滑入，表现为金属档案柜抽屉。
- 发现顺序可以编号，因为顺序来自真实的收录过程。
- 每张目录卡固定包含：收录序号、类型、标题、状态。
- 展开后显示解释文本和合法状态操作。
- 状态使用文字登记章，不使用圆角胶囊。
- 最终状态完成后，应明确说明记录不再变更。

状态视觉：

| 状态 | 文案 | 视觉语义 |
|---|---|---|
| `pending` | 待核 | 铅笔灰，尚未判断 |
| `verified` | 已核对 | 复写青，已确认来源 |
| `retained` | 保留 | 冷绿色，正式留下 |
| `held` | 悬置 | 暗黄色，位置仍然开放 |
| `discarded` | 移出 | 氧化印泥红，从现行解释中移出 |

### 7.5 随身物件

- 表现为页面左下方的证物托盘。
- 空状态只显示一条安静提示。
- 物件名称使用玩家认识的名称，不显示内部数据 ID。
- 展开层显示名称和数量，不扩展未实现的物品详情。

### 7.6 存档登记

- 使用登记表行布局。
- 每一行包含存档位名称、更新时间和操作。
- 时间使用等宽字体。
- 删除操作使用印泥色，但不抢过保存和读取操作。
- 不得改动现有存档结构或自动存档语义来配合视觉设计。

### 7.7 章节结算

- 表现为正式落卷页，不是奖励弹窗。
- 信息顺序为：卷宗信息 → 章节与主题 → 档案清点 → 结局正文 → 操作。
- 正文使用宋体，保留安静、不可完全解释的结尾气氛。
- 禁止使用庆祝粒子、胜利金色和评分星级。

### 7.8 Toast

- 位于 HUD 下方，不遮住底部对话。
- 使用深色记录条和复写青左边线。
- 文案说明发生了什么，例如“已收录档案”，不只显示“成功”。

## 八、Phaser 现实空间

当前主要实现位于：

- `app/src/game/constants.ts`
- `app/src/game/config.ts`
- `app/src/game/scenes/MapScene.ts`
- `app/src/game/objects/Decor.ts`
- `app/src/game/objects/Interactable.ts`

### 8.1 基准参数

```text
GAME_WIDTH   = 630
GAME_HEIGHT  = 891
TILE         = 42
PLAYER_SPEED = 210
```

`PLAYER_SPEED / TILE = 5`，保持原有每秒约五格的移动节奏。

### 8.2 镜头

- 镜头跟随玩家，宽地图通过移动镜头探索。
- 缩放根据地图高度计算，并限制在 `0.92–1.5`。
- 使用平滑跟随，不让镜头逐像素紧贴玩家。
- 设置适度死区，玩家在画面中央区域移动时镜头不频繁晃动。
- 开启整数像素渲染，保持程序化像素图形清晰。

### 8.3 地面与家具

- 地面保留极弱的档案网格，帮助表达空间尺度。
- 家具和碰撞块包含实体色、弱描边和短落地阴影。
- 不直接把碰撞格显示成明亮调试方块。
- 地点标签使用低透明度深色底，避免和地面混在一起。

### 8.4 互动对象

- NPC 使用偏纸色的圆形核心和印泥色轮廓。
- 普通物件使用复写青矩形核心。
- 所有互动对象必须有落地阴影、名称和邻近提示。
- `E` 提示使用等宽字体和纸色，不使用大型发光按钮。
- 已完成的一次性对象降低透明度，但仍保留空间痕迹。

### 8.5 出口

- 出口使用弱填充、边界和目标地点名称。
- 出口必须让玩家知道将前往哪里。
- 禁止重新使用高亮调试矩形作为正式出口表现。

## 九、动效

动效只服务于状态变化和纸张/抽屉的物理感。

| 场景 | 建议时长 | 规则 |
|---|---:|---|
| 标题复写归位 | 约 `900ms` | 每次进入标题页只执行一次 |
| 档案抽屉滑入 | 约 `220ms` | 短距离、减速落位 |
| Toast 出现 | 约 `180ms` | 小幅垂直移动 |
| 场景淡入 | 约 `220ms` | 保持现有 Phaser 淡入 |
| 按钮状态 | 约 `150ms` | 只变化颜色、边界和轻微位移 |

禁止：

- 所有卡片依次飞入。
- 持续漂浮的装饰。
- 大量滚动触发动画。
- 与档案主题无关的弹性、果冻或霓虹动画。

必须支持 `prefers-reduced-motion: reduce`，在该模式下把非必要动画缩短到近乎即时。

## 十、响应式与可访问性

### 10.1 响应式

- 页面比例始终是 A4，响应式只调整页面内部排版。
- `.game-app` 使用尺寸容器，内部组件通过 container query 响应实际页面宽度。
- 当前紧凑断点为页面宽度 `470px`。
- 在窄屏下缩小边距、元数据和标题，但正文不应小于可阅读尺寸。
- 档案抽屉和存档面板在窄屏下接近全页宽度。
- 存档操作在窄屏下允许换到第二行。

### 10.2 可访问性

- 所有按钮必须可通过键盘聚焦。
- 使用 `:focus-visible` 提供清晰纸色焦点框。
- 关闭按钮必须有 `aria-label`。
- 切换按钮使用 `aria-pressed` 表达当前状态。
- 正文与背景必须保持足够对比度。
- 状态不能只通过颜色表达。
- 纯视觉复写层必须使用 `aria-hidden="true"`。

## 十一、文案规范

- 从玩家能控制和识别的事物出发命名。
- 同一个动作在按钮、提示和结果中使用同一个词。
- 空状态给出下一步方向，例如“还没有收录任何档案。去房间里看看。”
- 错误说明发生了什么以及如何处理，不使用含糊的“操作失败”。
- 元数据可以使用机构化语气；主要操作继续使用自然中文。
- 不为了营造氛围添加与世界设定无关的英文。
- 英文只用于真实的档案编号、记录类型或界面辅助标识。

## 十二、实现约束

- 视觉修改不得改变剧情数据、地图坐标、碰撞规则和存档结构。
- 色彩必须从 `app/src/styles/index.css` 的 token 派生，禁止在组件内散落新的主题色。
- Phaser 地点专属颜色继续由地图数据提供，但公共交互颜色由游戏常量或共享规则控制。
- 新组件优先复用现有边界、字体和间距规则。
- 避免 `.section`、`.card` 等过宽选择器覆盖具体组件。
- 修改后必须运行类型检查、Lint、测试、数据校验和生产构建。
