# 《归档故乡》地图设计规范（竖屏 A4）

> 版本：1.0  
> 适用范围：Phaser 现实空间的地图几何与数据（`app/src/data/maps/maps.json`、`app/src/data/items/objects.json`、渲染现状）  
> 配套：《归档故乡》视觉规范（A4 单页系统）§8（Phaser 现实空间）  
> 核心命题：地图必须为竖屏而设计，而不是为横向而设计。

## 一、设计目标与原则

游戏视口是**竖向 A4**：`630 × 891`，比例 `210 : 297 ≈ 0.707`（即 `1 : √2`）。镜头按高度适配，因此地图的**宽度**直接决定水平平移量。

- 地图应**窄而高**：宽度被大幅收窄，内容**上下（纵向）排布**，让玩家主要沿竖屏方向移动。
- 保留**很轻的水平平移**可以接受，但不要出现需要左右拖很多屏的宽地图。
- 相机是"贴合竖屏"的：纵向恒定等于地图高，横向只有轻微跟随；这本身就是布局约束，不是可选项。

判断标准：一张 `W × H`（格）的地图，水平屏数 ≈ `W / (H × 0.707)`。
- `≤ 1.0`：完全贴合，无水平平移（适合小房间）。
- `1.1–1.35`：轻平移（可接受的目标区间）。
- `≥ 1.6`：用力过猛，需要收窄或增高。

## 二、竖屏视口与镜头（已核对源码）

| 项 | 值 | 位置 |
|---|---|---|
| 视口 | `630 × 891` | `constants.ts` `GAME_WIDTH/HEIGHT` |
| 格宽 | `42` | `constants.ts` `TILE` |
| 玩家速度 | `210` | `constants.ts` `PLAYER_SPEED` |
| 缩放 | `clamp(891 / mapH, 0.92, 1.5)`（`mapH = height*42`） | `MapScene.ts` |
| 跟随插值 | `0.09` | `MapScene.ts` |
| 死区 | `126 × 213.84`（`630*0.2 × 891*0.24`） | `MapScene.ts` |
| 整数像素 | 开启（`setRoundPixels(true)` + config `roundPixels`） | `MapScene.ts` / `config.ts` |

**水平可视换算**：纵向恒定等于 `mapH`，故水平可视格数 ≈ `630/zoom/42 = height * 0.707`。  
⇒ **收窄目标的经验公式**：宽度 ≈ `height × 0.707`（全贴合），或 ≤ `height × 0.95`（轻平移）。

**出生点常量**（布局改动必须同步，都是硬编码点）：
- `store.ts` `DEFAULT_START_POS`：新游戏/冷启动/开局 world 的落地格。
- `MapScene.ts` `beginExit` 兜底 `spawn`：仅"目标图无 spawn"时用。

## 三、几何重排规则

- **优先纵向组织**：把房间分区、家具、交互物沿 y 轴铺开；横向留出"一条走道"即可，不要横向铺开。
- **交互物放可走格**：每个交互物/NPC 所在格必须可走（不在 `solidTiles` 内），且从 `spawn` 可达。
- **出口是可走门洞**：出口 zone 的每个格子都必须是可达的可走格；进入后按 `id → to` 切图。
- **家具用实心簇**：`solidTiles` 只做碰撞体（`MapScene` 逐格建**不可见**物理体），视觉由 `furniture.ts` 按行聚成整块绘制。相邻同行的实心格自然合并成一块，无逐格接缝。
- **保留空间语义**：搬移分区时保持"这是什么地方"的直觉（餐桌配饭桌、档案室配柜列、菜市场配摊位）。
- **别把碰撞做成调试方块**：物理体 `debugShowBody = false`，避免 dev 下出现亮色方块。

## 四、数据模型（两文件）

### `maps.json` —— 地图（`LocationDef`，zod `locationDefSchema` strict）

| 字段 | 含义 | 运行时消费 |
|---|---|---|
| `id` | 地图 id，全局联接键 | `MapScene` 查表；交互物/出口/章节引用 |
| `name` | 显示名（可含 `·`，出口短名取第一个 `·` 前） | HUD / 出口标签 |
| `chapter` | 所属章（如 `"ch1"`） | — |
| `width` / `height` | 格数 | 物理边界、镜头边界、`bg` 地板尺寸 |
| `solidTiles` | `[x,y]` 数组，碰撞+家具簇 | 逐格建物理体 → `furniture.ts` 视觉 |
| `spawn` | `{x,y}` 默认出生格 | `data.spawn ?? loc.spawn` |
| `decorate` | `rect`（边框/陈设）与 `label`（地点标签） | `drawDecor` |
| `exits` | `{id,x,y,w,h,to}` 门洞 | 可视化 + 栅格级切图 |
| `interactables` | 交互物 **id 数组**（坐标在 `objects.json`） | 逐个从 `items` 查 |
| `bg` | `{color, accent}` 地板/家具实心色 | 地板 fill（`color`）、家具 run fill（`accent`） |

### `objects.json` —— 交互物/NPC（`InteractableDef`，zod `interactableDefSchema` strict）

`id / name / kind('object'|'npc') / location / x / y / interactRange / inspect / dialogue / provideArchive / requirements / unmetInspect / collect / once`。

**坐标在 `objects.json`，不在 `maps.json`。** 移动交互物 = 改这里；`location` + `id` 决定归属。

## 五、不可违背的约束（布局改动极限）

可改：`width/height`、`spawn`、`solidTiles`、`exits` 的 `x/y/w/h`、`decorate`、`objects.json` 的 `x/y`。

**不可改**（改了就是改剧情/存档）：
- 剧情节点与对白（`chapter01.json` 的 `nodes`、`intro`、`startMap`）。
- 存档结构与自动存档语义（`world`、`save`）。
- 交互物语义：`inspect`/`dialogue`/`provideArchive`/`requirements`/`unmetInspect`/`collect`/`once`。
- 出口连通：`exit.id → exit.to` 的映射；`objects.location → 地图` 的映射；地图 `id` 与 `chapter` 归属。
- 场景渲染的物理/碰撞规则（体积、速度、物理引擎配置）、数据 schema。

改动后必须保持：**门禁链可达**（如第一章集齐 4 份档案 → 母亲晚餐）、**交互物可交互**、**出口能到目标图**。

## 七、跨图连通与出生点

- 主起点：`DEFAULT_START_POS = { x: 8, y: 13 }`（即 home spawn）。新游戏/冷启动/开局初始化用；**改 home spawn 时必须同步**。
- 进图落点：`beginExit` 用 `data.spawn ?? loc.spawn`（`data.spawn` 来自上一张图的出口落点，或 `target.spawn`）。切图 `A→B` 落在 `B.spawn`。
- 出图落点：当前实现里进出某图都落在该图默认 `spawn`（无每出口定向 spawn），因此**交互物与出口不要压在 spawn 上**，避免落点即撞出口/被包围。
- 兜底：`target 无 spawn` 时用 `{ x: 8, y: 13 }`（与 `DEFAULT_START_POS` 一致）。

## 八、视觉呈现（当前实现要点）

颜色全部派生自 `index.css` `:root` token，Phaser 侧由 `constants.ts` `TOKENS` + `rgbToken`/`cssColor`/`cssRgba`/`darken` 提供，禁止散落硬编码新主题色。

| 对象 | 规范 |
|---|---|
| 地板 | `rgb(loc.bg.color)` 底色 + 极弱档案网格（`rgbToken('accent')` alpha 0.05）+ 四角暗晕（`rgbToken('bg0')` alpha 0.22） |
| 家具 | 按行 run 整块：填充 `rgb(loc.bg.accent)` alpha 0.98、落地阴影 `darken(bg0,0.55)` alpha 0.34、只描暴露边 `accentDim` 0.4；depth 0.8/1/1.1 |
| 交互物 | 物件核复写青 `accent`、NPC 核纸色 `paper` + 印泥红 `danger` 描边；邻近方块 tileColor 填充 0.12/描边 0.5；落地阴影椭圆 `darken(bg0,0.55)`；名称标签 `paper`/`cssRgba('bg0',0.76)`；container depth 5 |
| E 提示 | 等宽 `MONO_FONT` 13px、纸色 `cssColor('paper')`、`cssRgba('bg0',0.8)`、depth 20 |
| 出口 | 弱填充 `accent` 0.05 + 虚线边界 `accentDim` 0.4（dash 6 / gap 4）+ 目标名 `paper`/`cssRgba('bg0',0.8)` |
| 完成态 | `once` 已完成的交互物降至 alpha 0.45，仍留空间痕迹 |

关键色 token：`--bg-0 #11191a`、`--bg-1 #172224`、`--bg-2 #203033`、`--bg-3 #293a3c`、`--line #425355`、`--line-soft #2d3d3f`、`--accent #8fafb0`、`--accent-dim #668788`、`--paper #d0c8ae`、`--danger #9b554c`、`--keep #9aafa6`、`--hold #b7a36b`。

## 九、可达性硬校验（改动后必跑）

对每张图，从 `spawn` 在 `width×height` 内以 `solidTiles` 为障碍做 **BFS**，断言：
1. `spawn` 可走；
2. 每个交互物格可走、且**不在** `solidTiles` 内、且可达；
3. 每个出口 zone 的每个格可达、
4. `DEFAULT_START_POS`（home spawn）在 home 内可走、可达。

（实现时用一次性 TS/JS 脚本读 `maps.json` + `objects.json` 即可，不必入库。）

## 十、流程与验收清单

### 新增/修改地图流程
1. 定尺寸：`width ≈ height × (0.707 ~ 0.95)`，小房间全贴合、大场景轻平移。
2. 纵向排区：先定出口/交互物/家具簇的 y 分布，横向只留走道。
3. 写 `maps.json`（`width/height/spawn/solidTiles/exits/decorate/interactables` 顺序）+ 若移动交互物则改 `objects.json` 的 `x/y`。
4. 若改 **home** spawn：同步 `store.ts` `DEFAULT_START_POS` 与 `MapScene.beginExit` 兜底。
5. 跑步骤九的 BFS 可达性脚本；有不可达就调整 `solidTiles`。
6. 跑工程校验 + 实机走图。

### 工程校验（均须通过）
- `npm run typecheck` · `npm run lint` · `npm run test` · `npm run check:data` · `npm run build`
- 实机 `npm run dev` 走图：每张图在竖屏内主要上下活动、左右仅轻平移；家具为合并冷色块；出口虚线+目标名；交互物/NPC 可交互；进出图切换正常（尤其 home↔kitchen / home↔archive / home↔market）；无 console 错误。
